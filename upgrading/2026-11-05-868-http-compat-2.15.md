## HTTP compat moves to `~2.15` — an app pinning `~2.13` must move too

- **Version**: Unreleased
- **Nitro ref**: `Project.toml` `[compat]`; `src/core/lifecycle.jl` (`_precompile_listener`),
  `src/precompile.jl`, `src/routerhof.jl` (`_exact_leaf`), `src/core/pipeline.jl`
  (`_allowed_methods`); `test/http_internals_contract_tests.jl`, `test/precompilation_test.jl`,
  `test/routing_tests.jl`
- **Recorded**: 2026-11-05
- **Severity**: **breaking (dependency resolution)** — an app carrying its own `HTTP = "~2.13"`
  bound does not resolve against this release. Nothing in Nitro's own API changes.

### What changed

Nitro's bound moved from `HTTP = "~2.13"` to `HTTP = "~2.15"` (resolving 2.15.0, with Reseau
1.6.6, which Nitro's `Reseau = "~1.6"` already admits). **The pin stays `~`** for the same reason
as every earlier move: core reaches into HTTP internals no SemVer covers. Every internal canaried
in `test/http_internals_contract_tests.jl` keeps its layout and behavior at 2.15.0.

**Why now: `HTTP.precompile_server` (HTTP.jl issue #1553, PR #1555; 2.15).** It compiles a server's accept loop,
connection loop and HTTP/2 stream task for a handler type without running anything. Nitro's
precompile workload now warms a default `serve()`'s loop through it, in place of the private
`_serve_conn!` signature it named before (#827), so a fresh default server's first request still
compiles nothing of HTTP's own.

**One HTTP change needed a Nitro change.** Since HTTP 2.14 (HTTP.jl #1538) `HTTP.Router` stores
each literal route segment percent-decoded and decodes a request's segments before matching them.
Nitro already puts both the route (at registration) and the request target (in
`OriginFormMiddleware`) in one canonical percent-encoding (#351), so through Nitro a route matches
exactly the requests it matched before. Two of Nitro's own walks over the router's tree compared
the raw target, though, and would have disagreed with the router on a target that contains `%`:
the exact-route fast path would have served the route `/a%252F` (a literal `%2F` in its name) for
a request to `/a%2F`, and the `405` check would have answered that request `405` instead of
`404`. Both now hand any target with `%` to the router's own decoding, so neither can happen.

What an app can observe only when it uses HTTP.jl directly, none of which needs an app change
unless it relied on the old behavior:

- **An `HTTP.Router` the app builds itself** matches percent-decoded segments: `/%61dmin` takes
  the route `/admin`, and a route written `/caf%C3%A9` and one written `/café` are the same route.
  `HTTP.getparams` still returns the segment as sent. Nitro's own routing is unaffected (above).
- **`HTTP.fileserver` and `HTTP.servefile` called with a request path** split it before decoding
  it, so an encoded slash (`%2F`) gets `400` instead of acting as a separator, and so does a name
  ending in a dot or a space. Nitro's static and SPA mounts serve their own enumerated file list
  and do not go through it.
- **`HTTP.peeraddr`** returns `Reseau.TCP.SocketAddrV4` or `SocketAddrV6`, not the abstract
  `SocketAddr`. `getpeerip(req)` and `getip(req)` return what they returned before.
- **Client side** (an app using `HTTP.request` itself): a URL host that ends in a number must be a
  dotted-decimal IPv4 address, so `127.1`, `0x7f.1`, `2130706433` or `010.0.0.1` throws
  `ArgumentError`, including as a redirect `Location`.
- **A small response is written in one transport write with its head** (HTTP.jl #1547, 2.14.2),
  a `String` or byte-vector body of at most 4 KiB. Nothing observable changes but the syscall
  count.

**What did *not* change:** the router's results through Nitro, path params (still decoded once,
by Nitro), the body types, the non-consuming write path, the `HEAD` `Content-Length` handling of
2.13, and Nitro's public API. The HTTP/2 cancellation work in 2.15 does not reach Nitro, whose
listener is HTTP/1.x only.

### How to find the calls to migrate

```bash
# The app's own bound — this is what blocks resolution.
rg -n '^HTTP\s*=' <app>/Project.toml

# A router, file server or peer address the app takes from HTTP.jl directly.
rg -n 'HTTP\.(Router|register!|fileserver|servefile|peeraddr)' <app>/src

# Client URLs whose host is a bare or shortened number.
rg -n 'https?://[0-9x.]+[:/]' <app>/src <app>/config
```

### Migrate your app

```toml
# ✗ before — will not resolve against this release
HTTP = "~2.13"

# ✓ after
HTTP = "~2.15"
```

An app that does not pin HTTP itself needs no `Project.toml` change: it inherits the bound from
Nitro.
