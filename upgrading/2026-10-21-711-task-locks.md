## A worker store holds `TaskLocks` instead of implementing `lock_tasks` (#711)

- **Version**: Unreleased
- **Nitro ref**: [#711](https://github.com/PingoLee/Nitro.jl/issues/711) ; `src/Workers/registry.jl`, `ext/NitroPormGExt.jl`
- **Recorded**: 2026-10-21
- **Severity**: breaking (custom `AbstractWorkerStore` backends)

### What changed

`lock_tasks(callback, store)` was a required `AbstractWorkerStore` method, and both shipped stores
implemented it as one `ReentrantLock`. Nitro held it across every database statement of a submit,
a run start, a finish and a cancel. So one process pushed through one store call at a time,
whatever its connection pool: on a PormG store it topped out near 1 / (3 × statement round
trip) submit-to-completion cycles a second (#548).

The lock now covers **one task id**. A store holds a `Nitro.Workers.TaskLocks` and returns it
from the new required method `task_locks(store)`. Nitro implements
`lock_tasks(callback, store, task_id)` once, on top of it, and takes that id's stripe: two
sections on the same id still serialize, and two on different ids no longer wait for each other.
A store implements no locking itself any more.

- The contract row `lock_tasks` is replaced by `task_locks`, so `missing_store_methods` lists
  `task_locks` for a store that has not migrated. A pre-#711 `lock_tasks(callback, ::MyStore)`
  method is never called; the first locked operation (a submit, a cancel, `release_task!`, or the
  boot zombie sweep when `RUNNING` records exist) throws `StoreInterfaceError` naming
  `task_locks`.
- The two-argument `lock_tasks(callback, store)` and `lock_tasks(callback, runtime)` are gone.
  Code that took the store-wide lock to block the worker subsystem has nothing to take; take
  `lock_tasks(callback, store, task_id)` for the one id it is about.
- The watch authorizer (`set_watch_authorizer!`) now runs under the submitted key's stripe, not
  a store-wide lock. Its rules are unchanged (a pure in-memory predicate, no database query, no
  `fetch` of a task that touches the store), plus one that the store-wide lock used to forgive:
  **it must not call the worker API** (`submit_task`, `cancel_task`, `release_task!`, …). Such a
  call used to re-enter the one reentrant lock; on another key it now takes a second stripe, and
  two hooks doing that on two threads deadlock each other.
- `InMemoryWorkerStore`'s `task_lock` field is now `registry_lock`, and guards its `Dict` only.
  `PormGWorkerStore`'s `task_lock` field is replaced by `locks::TaskLocks`.

The zombie sweep and the shutdown abandon batch now lock one task at a time rather than holding
the lock for the whole batch. An external queue's `max_pending` and owner quota are counted under
an extra admission lock, so they stay exact against this process's own concurrent submits.

### How to find the calls to migrate

```bash
grep -rn -E 'lock_tasks|\.task_lock\b' --include=*.jl .
```

and the watch authorizers, to check none calls the worker API:

```bash
grep -rn -A15 'set_watch_authorizer!' --include=*.jl .
```

Each hit is one of:

- a backend's `lock_tasks(callback::Function, store::MyStore)` method — replace it with a
  `TaskLocks` field and a `task_locks` method;
- a direct call `lock_tasks(store) do … end` or `lock_tasks(runtime) do … end` — pass the task id
  the section is about;
- a read of an `InMemoryWorkerStore`'s `task_lock` field — it is `registry_lock` now;
- a watch authorizer that calls `submit_task`, `cancel_task` or `release_task!` — resolve what it
  needs before installing it instead.

A backend's own test suite catches the first one with
`@test isempty(missing_store_methods(MyWorkerStore))`.

### Migrate your app

```julia
# ✗ before: the backend owned the lock and implemented the locking method
struct MyWorkerStore <: Nitro.Workers.AbstractWorkerStore
    rows::Dict{String, Nitro.Workers.TaskInfo}
    lock::ReentrantLock
end
MyWorkerStore() = MyWorkerStore(Dict{String, Nitro.Workers.TaskInfo}(), ReentrantLock())
Nitro.Workers.lock_tasks(callback::Function, s::MyWorkerStore) = lock(callback, s.lock)

# ✓ after: the backend holds a TaskLocks and hands it out; Nitro takes it per task id
struct MyWorkerStore <: Nitro.Workers.AbstractWorkerStore
    rows::Dict{String, Nitro.Workers.TaskInfo}
    lock::ReentrantLock                 # still guards `rows`, if the backend needs that
    locks::Nitro.Workers.TaskLocks
end
MyWorkerStore() = MyWorkerStore(Dict{String, Nitro.Workers.TaskInfo}(), ReentrantLock(),
                                Nitro.Workers.TaskLocks())
Nitro.Workers.task_locks(s::MyWorkerStore) = s.locks
```

A wrapper store that forwarded the lock forwards the locks instead:

```julia
# ✗ before
Nitro.Workers.lock_tasks(cb::Function, s::Wrapper) = Nitro.Workers.lock_tasks(cb, s.inner)
# ✓ after
Nitro.Workers.task_locks(s::Wrapper) = Nitro.Workers.task_locks(s.inner)
```
