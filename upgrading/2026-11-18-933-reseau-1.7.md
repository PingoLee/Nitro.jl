## Reseau compat moves to `~1.7` — an app pinning `~1.6` must move too

- **Version**: Unreleased
- **Nitro ref**: #933 ; `Project.toml` `[compat]`; the comments naming the pin in
  `src/core/transport.jl` (`_peer_gone`) and `test/http_internals_contract_tests.jl`;
  `docs/src/tutorial/reverse_proxy.md`
- **Recorded**: 2026-11-18
- **Severity**: **breaking (dependency resolution)** — an app carrying its own `Reseau = "~1.6"`
  bound does not resolve against this release. Nothing in Nitro's own API changes.

### What changed

Nitro's bound on Reseau, HTTP.jl's transport, moved from `Reseau = "~1.6"` to `Reseau = "~1.7"`
(resolving 1.7.1, with HTTP 2.15.3, whose own compat already admits 1.7). **The pin stays `~`**:
the disconnect probe behind `cancel_reason(req)` reaches Reseau internals no SemVer covers, and
every one of them, canaried in `test/http_internals_contract_tests.jl`, keeps its name and
behavior on 1.7.

**Why: the two server timeouts stop costing the database routes throughput.** In Reseau 1.6,
every re-arm of a read deadline took the poller's one lock, which every socket wait in the process goes through, so
`serve()`'s default `read_header_timeout` and `idle_timeout` slowed every socket wait in the process,
the database driver's included. Reseau 1.7 gives the time heap its own lock
(JuliaServices/Reseau.jl#238). Measured on #782: on a route making 20 queries, a Nitro server on
its defaults served 1,677 requests per second against 1,676 with both timeouts at 0 on Reseau
1.7.0, and 1,467 against 1,686 on 1.6.6 in the same block. The defaults do not change.

That is the database routes. A route that does no work still pays for the re-arms themselves on
1.7: about 10% of throughput at `--threads=N,1` and about 2% at `N,0`, for Nitro and for HTTP.jl
alone (#782, the plain-text cell).

1.7.1 adds one TLS client fix over 1.7.0 (the server name of an IP-literal host is kept across a
TLS 1.3 to 1.2 fallback). Nitro's listener is plaintext.

### How to find the calls to migrate

```bash
# The app's own bound — this is what blocks resolution.
rg -n '^Reseau\s*=' <app>/Project.toml

# Reseau types or internals the app names itself.
rg -n 'Reseau' <app>/src
```

### Migrate your app

```toml
# ✗ before — will not resolve against this release
Reseau = "~1.6"

# ✓ after
Reseau = "~1.7"
```

An app that neither pins Reseau nor names it has nothing to do: it inherits the bound from Nitro.
An app that names Reseau internals should re-check them against 1.7, as Nitro's contract tests do
for its own.
