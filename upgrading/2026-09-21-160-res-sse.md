## `format_sse_message` is removed — SSE framing is `HTTP.SSEEvent`, and `Res.sse` is the builder (#160)

- **Version**: Unreleased
- **Nitro ref**: #160; `src/utilities/misc.jl`, `src/response.jl`, `src/Nitro.jl`,
  `src/core/transport.jl`
- **Recorded**: 2026-09-21
- **Severity**: **breaking (removed public export)** — `format_sse_message` no longer exists. Any
  app that builds SSE frames with it stops loading.

### What changed

`format_sse_message(data; event, id, retry)` is gone, export included. Server-Sent Events are now
built with `HTTP.SSEEvent` values written to the stream that the new [`Res.sse`](../docs/src/tutorial/streaming.md)
builder hands your producer. `SSEEvent` is re-exported from Nitro, so `using Nitro` is still all you
need.

**The replacement is not merely tidier — the old framer had an injection hole.** It rejected a line
feed in `event` and `id` but **not a carriage return**, and it split `data` on `'\n'` only. A bare CR
is a valid SSE line terminator on the wire and in every browser `EventSource` parser, so a single
attacker-influenced value could forge additional fields, or an early event boundary, in the stream
every connected client is reading. It also never rejected NUL in `id`, which the SSE specification
requires. `HTTP.SSEEvent` rejects CR and LF in both single-line fields — and NUL in `id` — and
re-emits every line break inside `data` as its own `data:` line where it cannot escape the event.

If your SSE payloads ever carried a `\r` — Windows-authored text, a CRLF-joined log line, a CSV cell
— your frames were already malformed and some clients were already seeing spurious events. That is
the bug this closes; it is not a new restriction on well-formed data.

Two things ship alongside, neither of which forces an edit:

- **`Res.sse`** returns an ordinary `HTTP.Response` whose body is an `HTTP.SSEStream`, so the whole
  middleware chain applies to an event stream. A `method = "STREAM"` handler marks the response as
  started, which makes Nitro skip the chain's response entirely — so `Cors`, `SecurityHeaders` and a
  session `Set-Cookie` were being silently dropped on every hand-rolled SSE route. Migrating to
  `Res.sse` fixes that as a side effect.
- **The streaming response writer now terminates on the short read** rather than pre-checking
  `body_closed`. "Closed" and "drained" are different states for a buffered body, so a producer that
  finished before the socket drained used to have its entire body discarded — a 200 with an empty
  event stream, silently. No app API changed.

### Who this affects

Only code that called `format_sse_message`. If you have no SSE endpoints, nothing here applies.

### How to find the calls to migrate

```bash
# 1. The removed function -- this is what blocks loading.
rg -n 'format_sse_message' <app>/src

# 2. Hand-rolled SSE routes. These keep working, but they are the ones silently losing their
#    CORS and security headers, so they are worth converting while you are here.
rg -n 'text/event-stream|method\s*=\s*"STREAM"' <app>/src

# 3. Payloads most likely to have carried a CR, i.e. where the old framer was actually unsafe.
rg -n 'format_sse_message\(' <app>/src | rg -i 'readline|read\(|log|csv|stderr|stdout'
```

### Migrate your app

```julia
# ✗ before -- hand-rolled framing on a raw stream. No middleware reached this response,
#             and a `\r` anywhere in `message` forged wire-level fields.
function events(stream::HTTP.Stream)
    HTTP.setheader(stream, "Content-Type" => "text/event-stream")
    HTTP.setheader(stream, "Cache-Control" => "no-cache")
    HTTP.setheader(stream, "Access-Control-Allow-Origin" => "*")   # by hand, because it had to be
    startwrite(stream)
    for message in messages
        write(stream, format_sse_message(message; event = "update"))
    end
    closewrite(stream)
end

path("/events", events; method = "STREAM")

# ✓ after -- an ordinary response, so Cors/SecurityHeaders/sessions apply as usual.
function events(req)
    return Res.sse() do stream
        for message in messages
            isopen(stream) || break        # the client hung up
            write(stream, SSEEvent(message; event = "update"))
        end
    end
end

path("/events", events)
```

The header set `Res.sse` sends is `Content-Type: text/event-stream`, `Cache-Control: no-cache` and
`X-Accel-Buffering: no`, with no `Content-Length` so the response is chunked and flushes per event.
Headers you pass are applied last and override those.

**There is no drop-in one-liner for the raw-stream form, on purpose.** `SSEEvent` is serialized only
by `write(::HTTP.SSEStream, ::HTTP.SSEEvent)` — `string(event)` gives you the struct's `repr`, not
wire bytes — so a `method = "STREAM"` handler cannot simply swap one call for another. That is the
push toward `Res.sse` above, which is also the form that stops dropping your middleware's headers.

If you genuinely must keep writing the socket yourself, frame it by hand **and validate the
single-line fields yourself** — that validation is the whole point of the change:

```julia
function sse_frame(data::AbstractString; event = nothing, id = nothing)
    for (name, value) in (("event", event), ("id", id))
        value === nothing && continue
        # CR and LF are both SSE line terminators. The spec requires the NUL rejection only
        # for `id`; rejecting it in `event` too is deliberately stricter and costs nothing.
        (occursin('\r', value) || occursin('\n', value) || occursin('\0', value)) &&
            throw(ArgumentError("SSE $name must not contain CR, LF or NUL"))
    end
    io = IOBuffer()
    event === nothing || write(io, "event: ", event, "\n")
    id === nothing || write(io, "id: ", id, "\n")
    # Every line break becomes its own `data:` line -- splitting on '\n' alone is the bug.
    for line in split(data, r"\r\n|\r|\n"; keepempty = true)
        write(io, "data: ", line, "\n")
    end
    write(io, "\n")
    return String(take!(io))
end
```

One behavior difference to expect: `SSEEvent` **throws** `ArgumentError` on a CR or LF in
`event`/`id` (and on a NUL in `id`), where `format_sse_message` threw only on LF. Sanitize those fields, or move the value
into `data`, which accepts line breaks by design. `SSEEvent` also accepts `retry = 0`, which the old
function rejected.
