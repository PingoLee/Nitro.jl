## `serve()` — a request may carry at most 1000 fields per source (`max_fields`)

- **Version**: Unreleased
- **Nitro ref**: [#327](https://github.com/PingoLee/Nitro.jl/issues/327) ; `src/constants.jl`,
  `src/core/lifecycle.jl`, `src/core/pipeline.jl`, `src/utilities/bodyparsers.jl`, `src/types.jl`
- **Recorded**: 2026-09-24
- **Severity**: behavior change — a request with more than 1000 query parameters, urlencoded form
  fields, multipart parts, or JSON object keys, which used to be served, is now a `400`.

### What changed

`serve` takes a new keyword, `max_fields`, defaulting to `DEFAULT_MAX_FIELDS = 1000`, with `0`
meaning unlimited. Each source is counted on its own, before its fields are hashed into a `Dict`:

| Source | Counted | Over the cap |
|---|---|---|
| query string | non-empty `&`-separated fields | `getquery`, `payload`, typed query params, `Query{T}` → `400` |
| urlencoded form body | the same | `getform`, `payload`, `Form{T}`, `CSRFMiddleware`'s form token lookup → `400` |
| multipart body | parts | `getfiles`, `getpost`, `multipart`, `MultipartForm{T}` → `400` |
| JSON body | object keys across the whole document, nested objects included | `getjson`, `json(req)`, `json(req, T)`, `payload`, `Json{T}`, `JsonFragment{T}` → `400` |

The byte caps (`max_body_bytes`, the request-line limit) bound how much a request sends, not how
many keys it packs into that, and every one of these sources becomes a string-keyed hash table.
`hash(::String)` has a fixed seed, so a client that picks its own keys can pick colliding ones.
1000 is Django's `DATA_UPLOAD_MAX_NUMBER_FIELDS` and Express's `urlencoded` `parameterLimit`.

The cap is per server and also governs `internalrequest` against that app. A parser called outside
any request (a test, a script) uses the default, 1000. `json(res)` on an `HTTP.Response` is not
capped. The error message names the source and the cap, never a key.

Note that `json(req)` and `getjson` answer an over-cap body with a `ValidationError` (a `400`), not
with `nothing`: the body is valid JSON that the server refuses, not malformed input.

### How to find the calls to migrate

```bash
# Apps that legitimately accept very wide requests: bulk-edit forms, large JSON maps.
rg -n 'Form\{|getform\(|getpost\(|MultipartForm\{|Json\{|getjson\(|json\(req' <app>/src

# Where the server is started, to raise the cap there.
rg -n 'serve\(' <app>/src
```

### Migrate your app

```julia
# ✗ before — a 2,500-field bulk-edit form was accepted
serve(app; port = 8080)

# ✓ after — raise the cap for this server (or `0` to lift it)
serve(app; port = 8080, max_fields = 5_000)
```
