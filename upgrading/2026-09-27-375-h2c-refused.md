## `serve()` — cleartext HTTP/2 (h2c) is refused; the listener speaks HTTP/1.x only (#375)

- **Version**: Unreleased
- **Nitro ref**: [#375](https://github.com/PingoLee/Nitro.jl/issues/375) ; `src/core/lifecycle.jl`
- **Recorded**: 2026-09-27
- **Severity**: **behavior change.** It affects only a deployment whose proxy, load balancer or
  client talks to Nitro in cleartext HTTP/2 on purpose. Browsers never do, and nginx's
  `proxy_pass` never speaks HTTP/2 upstream either.

### What changed

HTTP.jl checks every plaintext connection for the cleartext HTTP/2 "prior knowledge" preface
(`PRI * HTTP/2.0`) and, when it finds one, serves the connection as HTTP/2. It has no option to
turn that off, so every `serve` listener accepted h2c from any client that asked. Nitro's request
handling was written for HTTP/1.1 and was not safe on HTTP/2 streams. For example, a `413` or `503`
refusal could not bound its wait for a body that never arrived, and so held a
`max_concurrent_requests` slot forever.

`serve` now refuses h2c. The preface goes to the HTTP/1.1 parser, which answers `400` and closes
the connection. HTTP/1.x is unchanged. There is no switch to turn h2c back on: put HTTP/2 at the
proxy, which is also where TLS belongs.

### How to find the calls to migrate

There is nothing to change in Julia code. Check how each proxy or platform in front of Nitro is
configured to reach it:

```bash
grep -rniE "h2c|versions +h2|http2_protocol_options|use-http2|end-to-end HTTP/2" \
  deploy/ infra/ /etc/caddy/ /etc/envoy/ 2>/dev/null
```

A client that hits the refusal fails immediately with a protocol error. Its `400` reply is an
HTTP/1.1 status line, which an HTTP/2 client cannot parse.

### Migrate your app

```text
# ✗ before — Caddy speaking cleartext HTTP/2 to Nitro
reverse_proxy 127.0.0.1:8080 {
    transport http {
        versions h2c
    }
}

# ✓ after — HTTP/1.1 upstream (Caddy's default); keep HTTP/2 between the client and Caddy
reverse_proxy 127.0.0.1:8080
```

The same applies elsewhere. An Envoy cluster pointed at Nitro drops its HTTP/2 protocol options,
and a Cloud Run service turns off "Use HTTP/2 end-to-end".
