## `ProtoBuffer{T}` and `protobuf(req, T)` — protobuf bodies are decoded under length, depth and merge bounds (#325)

- **Version**: Unreleased
- **Nitro ref**: [#325](https://github.com/PingoLee/Nitro.jl/issues/325) ; `ext/ProtoBufExt.jl`
- **Recorded**: 2026-09-25
- **Severity**: **behavior change.** It affects apps that load ProtoBuf.jl and accept protobuf
  bodies, through the `ProtoBuffer{T}` extractor or a direct `protobuf(req, T)` /
  `protobuf(res, T)` call. Bodies no conforming encoder produces are now refused, and so is
  protobuf that is legal but extreme: nesting deeper than 100 levels, or more than 16 merges of
  repeated singular sub-message fields in one body.

### What changed

ProtoBuf.jl's decoder believes what a message says about itself. A request body is written by
whoever sent it, so a few bytes and no authentication were enough for any of these:

- **A 4 GiB allocation from a 6-byte body.** A string, or a packed fixed-width field, allocates
  its length prefix *before* reading it. `0a ff ff ff ff 0f` asks for 4 GiB, and `max_body_bytes`
  cannot help, because the body really is 6 bytes. On a host that commits memory strictly, a
  few of those at once start failing everyone else's allocations.
- **A stack overflow.** Sub-messages and groups recurse once per level with no limit. A body of
  nested group tags needs no particular schema, since unknown fields are skipped recursively. The
  overflow was a `500`, and on some Windows hosts a dead process (#301).
- **Quadratic work.** Each repeat of a singular sub-message field merges into the one before and
  re-copies its repeated fields. A 140 KB body allocated ~770 MiB.
- **Silently truncated fields.** A `bytes` field, or an unknown field being skipped, whose prefix
  claimed more than the body held decoded as whatever was there.
- **Uninitialized memory.** A packed fixed-width or float field that followed an unpacked element
  of the same field came back holding uninitialized memory.

Nitro now decodes through a bounded decoder of its own. Code generated by both current and older
ProtoBuf.jl releases goes through it:

| Body | Before | After |
|---|---|---|
| A string, bytes, packed fixed-width, sub-message or skipped unknown field whose length prefix is longer than the rest of the body | Allocated the claimed length, then `EOFError`. A `bytes` or skipped field was silently truncated | Refused before any allocation |
| Sub-messages or groups nested deeper than **100** levels | Decoded, or overflowed the stack once deep enough | Refused at level 101 |
| More than **16** merges in one body. A merge happens each time a singular sub-message field appears again, counted across all fields and levels | Merged, at quadratic cost | Refused at the 17th merge |
| A packed fixed-width run whose length is not a multiple of the element size | `AssertionError` | Refused |
| A packed fixed-width run after an unpacked element of the same field | Uninitialized memory in the result | Both parts decoded |

"Refused" means a `400` through `ProtoBuffer{T}`. From a direct `protobuf(req, T)` or
`protobuf(res, T)` call it means an `ArgumentError`, whose message never quotes the body. The
limits are fixed, and there is no setting. 100 is the default recursion limit of Google's own
protobuf parsers.

Every other malformed body fails as it did before, with ProtoBuf.jl's own errors. For example,
a body that ends mid-field is an `EOFError`, and a packed varint run cut short is an
`AssertionError`. Others surface as `ErrorException`, `InexactError` or `MethodError`. So a
direct decode can fail with several exception types on bad input, `ArgumentError` among them.

### How to find the calls to migrate

```bash
# 1. Where the app decodes protobuf at all. No hit, nothing to do.
rg -n 'ProtoBuffer\{|protobuf\(' <app>/src

# 2. Code that catches specific failure types from a direct decode. The bounded cases above
#    now throw ArgumentError; everything else still throws what it did.
rg -n 'EOFError|AssertionError' <app>/src

# 3. Schemas that can legitimately nest past 100 levels: a message that contains itself
#    (a tree, a linked list) is the only way to get there.
rg -n 'message\s+(\w+)\s*\{' -A20 <app> --glob '*.proto'   # look for a field of the message's own type
```

A client that concatenates encoded messages to merge them is the only legitimate producer of a
repeated singular sub-message. Concatenating `N` messages that each set `k` singular
sub-message fields causes `k × (N − 1)` merges, and fails once that passes 16.

### Migrate your app

A direct decode that treated one exception type as "bad body" misses the others. Catch
everything except the three conditions no body should be blamed for:

```julia
# ✗ before -- an ArgumentError from the bounds would now escape as a 500
msg = try protobuf(req, MyMessage) catch e
    e isa EOFError || rethrow()
    return Res.status(400)
end

# ✓ after -- or take the message through ProtoBuffer{MyMessage}, which does exactly this
msg = try protobuf(req, MyMessage) catch e
    e isa Union{InterruptException, StackOverflowError, OutOfMemoryError} && rethrow()
    return Res.status(400)
end
```

A recursive message that really nests past 100 levels has to be sent flatter, because the limit
cannot be raised:

```protobuf
// ✗ before -- a tree as nested children, any depth
message Node { int64 id = 1; repeated Node children = 2; }

// ✓ after -- a flat list with parent links, rebuilt by the handler
message Node { int64 id = 1; int64 parent = 2; }
message Tree { repeated Node nodes = 1; }
```
