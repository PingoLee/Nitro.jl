## JSON compat floor moves to `1.13.4` — an app pinning JSON below it must move too

- **Version**: Unreleased
- **Nitro ref**: `Project.toml` `[compat]`; `docs/design/juliac-trim.md` §3.9 and §4 step 7
- **Recorded**: 2026-11-02
- **Severity**: **breaking (dependency resolution)** — an app whose own `Project.toml` bounds
  `JSON` below `1.13.4` (`"1.12.1"`, `"~1.13.2"`, `"=1.13.0"`, …) does not resolve against this
  release. Nothing in Nitro's API or behavior changes.

### What changed

Nitro's bound moved from `JSON = "1.12.1"` to `JSON = "1.13.4"`. JSON.jl 1.13.0 through 1.13.3
carry [JuliaIO/JSON.jl#553](https://github.com/JuliaIO/JSON.jl/issues/553): a typed `JSON.parse`
under a custom read style, which Nitro's scalar-parameter fall-through uses
(`_parseparam_fallback`, `style = NITRO_READ_STYLE`), is not verifiable under `juliac --trim`, and
an executable built without verification can throw a `MethodError` at run time on such a parse.
JSON.jl 1.13.4 fixes it (#555). Under the JIT the four versions behave the same; the floor exists
so that a `--trim` build's verifier count does not depend on the day the environment was resolved
(Nitro [#801](https://github.com/PingoLee/Nitro.jl/issues/801): 231 rows on 1.13.0, 121 on 1.13.4
and on 1.12.2).

**What did *not* change:** the body parsers, the extractors, `Res.json`, the JWT claims read and
every documented JSON behavior; the 1.12.x behaviors already in this log (the `400` on a bad
escape in an ignored field) are unchanged.

### How to find the calls to migrate

```bash
# The app's own bound — this is what blocks resolution.
rg -n '^JSON\s*=' <app>/Project.toml
```

### Migrate your app

```toml
# ✗ before — will not resolve against this release
JSON = "1.12.1"

# ✓ after
JSON = "1.13.4"
```

An app that does not pin JSON itself needs no `Project.toml` change: it inherits the bound from
Nitro.
