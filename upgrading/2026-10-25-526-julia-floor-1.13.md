## Nitro requires Julia 1.13

- **Version**: Unreleased
- **Nitro ref**: `Project.toml` (`[compat] julia`), `src/newapp.jl` (`_NEWAPP_JULIA_COMPAT`)
- **Recorded**: 2026-10-25
- **Severity**: breaking (an application on Julia 1.12 no longer resolves Nitro)

### What changed

Nitro's `[compat]` entry for Julia moves from `julia = "^1.12"` to `julia = "^1.13"`
([#526](https://github.com/PingoLee/Nitro.jl/issues/526)). On Julia 1.12, `Pkg` can no longer
resolve a Nitro that carries this entry: anything that resolves (`Pkg.add`, `Pkg.resolve`,
`Pkg.update`, or `Pkg.instantiate` with no manifest or one out of sync with the project) fails
with an unsatisfiable requirement for `julia`. An application already resolved against an older
Nitro keeps running until it moves its pin. `Nitro.newapp` now scaffolds `julia = "^1.13"` too.

CI has tested only the 1.13 series since the first half of #526, so the declared floor now names
the configuration that is tested.

**What the move buys.** Julia 1.12 on macOS can start a process whose SIGINT is ignored for its
whole life: the kqueue signal-listener thread races the main thread installing the real handler.
In two runs of 200 bare 1.12 processes on macOS, 7 and 10 started that way (PR #477), and a
`serve()` in such a process cannot be stopped with Ctrl-C. JuliaLang/julia#62471 fixes it in
1.13.0, so on the supported range Ctrl-C always reaches the process. Nitro's own tests no longer
retry around it.

**What it does not change.** Every released 1.13.x has the #586 scheduler stall
(JuliaLang/julia#63882): a task parked on a `Timer` may not wake while every `:default` thread runs
a handler that calls `yield()`. `serve()` and `consume!` keep holding the wake guard on the
affected 1.13.x releases, exactly as before; [#609](https://github.com/PingoLee/Nitro.jl/issues/609)
tracks lowering and then removing it once a fixed 1.13.x ships.

### How to find the calls to migrate

```bash
# The Julia that runs the app, locally and in every deploy target:
julia --version
# The app's own declared floor:
grep -n -E '^julia *=' Project.toml
# Deploy images and CI jobs that pin a Julia version:
grep -rn -E 'FROM +julia|julia:1\.|julia-version|setup-julia|version: *.?1\.1' \
  --include='Dockerfile*' --include='*.yml' --include='*.yaml' .
```

### Before → after

Raise the app's own `[compat]` entry, then its runtime, then re-resolve:

```toml
# before
[compat]
julia = "1.12"

# after
[compat]
julia = "1.13"
```

```bash
juliaup add 1.13 && juliaup default 1.13      # local
# Dockerfile: FROM julia:1.12  →  FROM julia:1.13
# CI:         version: '1.12'  →  version: '1.13'
julia --project -e 'using Pkg; Pkg.resolve(); Pkg.instantiate()'
```

A `Manifest.toml` written by 1.12 is re-resolved by 1.13 on that `Pkg.resolve()`; commit the
result if the app commits its manifest.
